## Функциональные требования

| ID | Требование | Проверка |
|---|---|---|
| LUNI-01 | Один документ index.html; навигация по якорям | Прямое открытие якоря, Back/Forward, работа ссылок без JS |
| LUNI-02 | Все семь секций 01–07 в указанном порядке, включая Why Luni | DOM и визуальное сравнение с каждым PNG |
| LUNI-03 | Адаптивность всего лендинга | 375/768/1440 px, промежуточные ширины, без переполнений |
| LUNI-04 | Общий каталог Monthly/Yearly и согласованная сводка | Выбор обоих вариантов; неизвестная цена отображается как «—» |
| LUNI-05 | Get Luni / Discover Luni → #plans; See how it works / Explore the app → #the-app; Choose plan → #checkout | Переходы внутри документа без перезагрузки |
| LUNI-06 | Support: контент по скриншоту; без корпуса статей поиск явно недоступен | Нет выдуманных результатов и ложного успеха |
| LUNI-07 | Изображение VPN не обозначает реальное подключение | Мобильные макеты используются как демонстрация приложения |
| LUNI-08 | Checkout и Account входят в лендинг как demo-секции | Нет реальной оплаты, авторизации и сохранения реквизитов |
| LUNI-09 | Сохранить английские подписи и светлую фирменную палитру | Тексты по PNG, lang=en |
| LUNI-10 | Обещания продукта и коммерческие условия проверяются перед релизом | Проверка владельцем продукта |

Checkout и Account остаются в потоке и при отсутствии выбранного тарифа. Выбор обновляет сводку; query `plan=monthly|yearly` может сохранять выбор при ссылке `?plan=monthly#checkout`. Отсутствующий/неверный plan не создаёт товар: показать приглашение выбрать тариф.

## Архитектура и качество

Webpack + Handlebars + SCSS + vanilla JS; целевой результат — один index.html и ресурсы. Общая шапка и меню, один main/h1, секции с h2 и уникальными id. Повторяющиеся шапки на PNG трактуются как контекст макета; в документе используется общая шапка. Не делать семь полноэкранных растровых картинок вместо интерфейса.

Основной контент и якоря доступны без JS. Клавиатура, видимый фокус, подписи полей, aria-состояния, Escape и возврат фокуса у диалога. Учитывать reduced motion, увеличение текста и масштаб 200%. Не прятать заголовок якоря под шапкой. Проверить Chromium/Firefox/WebKit; успешный прогон фиксируется отдельно.

Мобильные PNG приложения не являются мобильной вёрсткой лендинга. На телефоне сохранить порядок 01–07: текст перед иллюстрацией, карточки в колонку, сводка после формы. Не использовать оболочку телефона для всего сайта.

Один title/description/canonical для лендинга. Preview с демонстрационными данными может целиком использовать noindex; robots не задаётся отдельно для якоря. Домен, публикация, реальные цены, контакты поддержки, платежи и аккаунты остаются отдельными зависимостями. Они не блокируют вёрстку по концепту.

Проверенный `webpack/pages.js` пока содержит шесть HTML: index/app/support/plans/checkout/account. Это прежняя реализация, которую предстоит объединить; обновление docs само по себе код не меняет. Приёмка единого лендинга ещё не выполнена. Account/Billing API — будущий контур, backend вишлиста учитывается отдельно в [status](backend/status.md).
