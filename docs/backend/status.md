# Backend LuniVPN: фактическое состояние

Реализован локальный MVP Telegram-вишлиста по образцу Nordel. Основные файлы: [common.php](../../tg-bot/common.php), [webhook.php](../../tg-bot/webhook.php), [webhook-admin.php](../../tg-bot/webhook-admin.php), [compose.yaml](../../compose.yaml). Это отдельный backend для вишлиста; API аккаунта, оплаты, подписки и VPN из [api-contracts.md](api-contracts.md) остаётся проектом, endpoints не существуют.

## Поток данных

Сайт должен вести на собственного Telegram-бота LuniVPN. Пользователь сам отправляет `/start` в личном чате. Telegram отправляет HTTPS POST на `/webhook` через ngrok (локально) или production ingress. Обработчик проверяет секрет, размер и формат, затем сохраняет пользователя в `/data/wishlist.json` и отправляет приветствие. Лишь успешная запись предшествует сообщению. Клик по ссылке на сайте сам по себе ничего не сохраняет. Публичная ссылка на конкретного бота пока не задана, поэтому сквозной переход с сайта не готов.

## HTTP-контракт

| Запрос | Ответ |
|---|---|
| GET /health | 200 `ok`, если задан валидный токен и секрет; Telegram и запись не проверяются |
| POST /webhook без правильного `X-Telegram-Bot-Api-Secret-Token` | 403 |
| POST /webhook, тело больше 65536 байт | 413 |
| POST /webhook, неверный JSON, корень не объект, нет целого `update_id` или неверная структура релевантного сообщения | 400 |
| POST /webhook, нерелевантное событие | 200 без записи |
| POST /webhook, корректный `/start` | upsert по Telegram ID, `sendMessage`, 200 |
| Сбой хранения или Telegram API | 500, безопасное сообщение; Telegram может повторить событие |
| Любой иной путь/метод | 404; PHP-исходники и JSON не отдаются |

Команды `/start`, `/start <аргумент>`, `/start@bot` распознаются; `/starter` игнорируется. Принимается только `message` из private chat с совпадающими целочисленными `from.id` и `chat.id`. Никакие аргументы команды не исполняются.

## Хранилище и отказы

JSON — массив записей `telegramId`, `username`, `firstName`, `lastName`, `createdAt`, `lastStartAt`. Поля имён могут быть null. Ключ — `telegramId`, время UTC. Повторный старт меняет имена и `lastStartAt`, сохраняя `createdAt`. Отдельный файл `.lock` и `flock` сериализуют записи; временный файл в том же каталоге и `rename` заменяют JSON. Некорректный JSON останавливает запись и сохраняется для разбора. В Compose данные живут в именованном volume `luni-vpn_wishlist`; `down -v` его удаляет.

Повторная доставка события может отправить повторное приветствие: `update_id` не сохраняется. Если запись прошла, а Telegram API отказал, запись остаётся, HTTP отвечает 500; retry обновит её без второго пользователя. Исходящий запрос имеет timeout 15 секунд. JSON подходит только для одного узла и малого вишлиста.

## Запуск и эксплуатация

Локальные команды, переменные, регистрация webhook, backup и восстановление описаны в [docker-compose.md](docker-compose.md). `php -S` и ngrok предназначены для локального стенда; production требует отдельного HTTPS ingress и HTTP runtime. Сайт через ngrok не публикуется. Текущий frontend deploy не развёртывает бот. Polling в [bot.php](../../tg-bot/bot.php) альтернативен webhook и не должен идти одновременно; его offset хранится только в памяти.

## Проверки в этом изменении

- PHP 8.4.12: `php -l` для четырёх PHP-файлов — прошло.
- Docker Compose: `docker compose config --quiet` с синтетическими переменными — прошло.
- `php tests/backend/wishlist.php`: upsert, сохранение `createdAt`, ключ по ID, игнорирование групп и чужих команд, отказ от повреждённого JSON — прошло.
- `docker compose build bot` с синтетическими переменными — прошло на Docker 29.8.2.\n- `npm run build:prod` локально — прошло. `docker compose build site` дважды остановлено по лимиту 60 секунд во время скачивания базовых образов; результат Docker-сборки сайта не установлен.\n- Работа контейнера, HTTPS wrapper внутри образа, webhook с реальным ботом, сохранение после пересоздания контейнера и backup/restore на volume — не проверены. Для сквозного прогона нужны собственные токены и URL.

Подробная матрица дальнейшей приёмки: [wishlist-validation.md](wishlist-validation.md). До публичного запуска определить политику доступа, хранения и удаления персональных данных.
