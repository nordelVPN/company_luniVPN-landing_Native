# task-009 · Реализовать demo Checkout и сценарий выбора плана

## Актуальный объём: единый лендинг

Demo Checkout — секция 06 `#checkout` и включена в текущий объём. Не ожидает согласования task-002. Выбор любого из четырёх тарифов (`trial`, `basic`, `plus`, `complete`) и сводка работают в одном DOM, допускается query `?plan=trial|basic|plus|complete#checkout` для прямой ссылки. При выбранном тарифе сводка показывает его название и цену из каталога (`0.50` / `7` / `25` / `55`, без произвольной валюты до её подтверждения); при отсутствующем/неверном тарифе Total = «—».

Основа: [requirements](requirements.md) и [task-001](task-001.md). Порядок: Home → The app → Why Luni → Support → Plans → Checkout → Account. Эта запись заменяет прежние требования об отдельных страницах, двух тарифах Monthly/Yearly и ожидании согласования количества экранов. Выполнение миграции и QA пока не подтверждены.

## Ранее зафиксированные детали и отчёты

Ниже сохранены детали прежней реализации. Упоминания MPA, отдельных HTML, двух тарифов и старых зависимостей являются историческими; применять актуальный объём выше.


**Исполнитель:** Frontend  
**Статус:** включена в текущий объём единого лендинга  
**Первый показ:** Get Luni → Trial / Basic / Plus / Complete → Checkout с одинаковым выбранным планом, ценой из каталога и явной маркировкой demo.

## Объём работ

- [ ] Сверстать выбранный план, демонстрационную платёжную область и сводку по desktop-концепту; на узком экране сводку разместить после формы.
- [ ] Читать `plan` из URL (`trial`, `basic`, `plus`, `complete`) и проверять по общему каталогу. При отсутствующем/неверном `plan` показывать приглашение выбрать план, а не автоматически выбирать товар.
- [ ] Отображать цену выбранного тарифа из каталога (`0.50` / `7` / `25` / `55`, валюта после подтверждения) и Total «—» при отсутствии/неверном выборе; сделать demo-маркер видимым до действия.
- [ ] Визуальные реквизиты сделать синтетическим не редактируемым макетом; не собирать настоящие номера карт/CVC и не сохранять чувствительные поля.
- [ ] `createCheckout` через demo-сервис возвращает `unavailable`; UI объясняет отсутствие оплаты. Обработать ошибку адаптера и повторное действие без ложного успеха.
- [ ] Не делать live API или платёжный SDK.

**Планируемые файлы:** `src/templates/partials/sections/checkout.hbs`, `src/modules/checkout.js`, `src/services/demo/*`, стили checkout.

## Проверка результата

1. `trial`, `basic`, `plus`, `complete` сохраняются при переходе и перезагрузке (`?plan=...#checkout`); неизвестный, пустой и отсутствующий `plan` дают безопасное предложение выбора и Total «—».
2. Кнопка продолжения сообщает о недоступности оплаты, не показывает успешный заказ и не выполняет платёжных запросов.
3. На 375/768/1440 px поля/макеты и сводка читаются, порядок фокуса и label корректны.
4. Unit-проверки ошибок адаптера и E2E всех четырёх путей выбора проходят; без JS видны demo-пояснение и обычная ссылка на тарифы.
