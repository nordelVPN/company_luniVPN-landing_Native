# task-009 · Реализовать demo Checkout и сценарий выбора плана

## Актуальный объём: единый лендинг

Demo Checkout — секция 06 #checkout и включена в текущий объём. Не ожидает согласования task-002. Выбор тарифа и сводка работают в одном DOM, допускается query plan для прямой ссылки.

Основа: [requirements](requirements.md) и [task-001](task-001.md). Порядок: Home → The app → Why Luni → Support → Plans → Checkout → Account. Эта запись заменяет прежние требования об отдельных страницах и ожидании согласования количества экранов. Выполнение миграции и QA пока не подтверждены.

## Ранее зафиксированные детали и отчёты

Ниже сохранены детали прежней реализации. Упоминания MPA, отдельных HTML и старых зависимостей являются историческими; применять актуальный объём выше.


**Исполнитель:** Frontend  
**Статус:** ожидает согласования объёма B в task-002  
**Первый показ:** Get Luni → Monthly/Yearly → Checkout с одинаковым выбранным планом и явной маркировкой demo.

## Объём работ

- [ ] Сверстать выбранный план, демонстрационную платёжную область и сводку по desktop-концепту; на узком экране сводку разместить после формы.
- [ ] Читать plan из URL и проверять по общему каталогу. При отсутствующем/неверном plan показывать приглашение выбрать план, а не автоматически выбирать товар.
- [ ] Показать Total «—» при неизвестной цене; сделать demo-маркер видимым до действия.
- [ ] Визуальные реквизиты сделать синтетическим не редактируемым макетом; не собирать настоящие номера карт/CVC и не сохранять чувствительные поля.
- [ ] createCheckout через demo-сервис возвращает unavailable; UI объясняет отсутствие оплаты. Обработать ошибку адаптера и повторное действие без ложного успеха.
- [ ] Добавить маршрут только после включения задачи в итерацию; исключить demo из индексируемого sitemap, не делать live API или платёжный SDK.

**Планируемые файлы:** pages/checkout.hbs, src/entries/checkout.js, src/data/pages/checkout.js, src/templates/partials/checkout/*, src/modules/checkout.js, src/services/demo/*, стили checkout.

## Рабочие допущения

**Зависимости:** task-005/006/007; task-002 определяет включение Checkout и состав demo-полей с учётом D04.

На момент постановки исходники frontend и package.json отсутствуют. Эта карточка описывает недостающую реализацию, а не выполненную работу. Стек и разделение слоёв берём из обновлённой архитектуры. Этап C, реальная оплата, авторизация и VPN в задачу не входят.

## Проверка результата

1. Monthly/Yearly сохраняются при переходе и перезагрузке; неизвестный, пустой и отсутствующий plan дают безопасное предложение выбора.
2. Кнопка продолжения сообщает о недоступности оплаты, не показывает успешный заказ и не выполняет платёжных запросов.
3. На 375/768/1440 px поля/макеты и сводка читаются, порядок фокуса и label корректны.
4. Unit-проверки ошибок адаптера и E2E обоих путей выбора проходят; без JS видны demo-пояснение и обычная ссылка на тарифы.
