# task-013 · Переливающаяся home-wave на canvas

**Исполнитель:** Frontend  
**Статус:** запланировано, можно брать в работу  
**Приоритет:** визуальное улучшение Home  
**Первый показ:** плавное движение складок и световых переливов существующей home-wave в секции #home, с замерами времени кадра.

## Основание и текущее состояние

Основа — [концепт Home](images/concept/desktop/list-screens/01-home.png), существующие [home-wave.webp](../src/assets/illustrations/home-wave.webp) / [home-wave.png](../src/assets/illustrations/home-wave.png) и [спецификация графики](frontend/visual-assets-spec.md).

При постановке задачи волна уже подключена статическим фоном через `.section-home::before` в [index.scss](../src/styles/pages/index.scss). В [home.hbs](../src/templates/partials/sections/home.hbs) отдельного canvas нет; в [index.js](../src/entries/index.js) подключены navigation, checkout и wishlist. В src/modules нет wave-модуля, поиск requestAnimationFrame в src не дал совпадений; Three.js в package.json отсутствует. Это задача на анимацию существующей графики, не повторное изготовление ассетов.

Связи: [task-004](task-004.md) — визуальный эталон и статический fallback, [task-006](task-006.md) — Home, [task-011](task-011.md) — приёмка. Прототип можно делать сразу; финальное подключение проверять в едином лендинге.

## Объём работ

- [ ] Реализовать декоративный canvas в #home: медленное непрерывное течение слоёв, мягкая деформация складок и перемещение бликов. Простого сдвига/вращения целого изображения недостаточно.
- [ ] Сохранить силуэт, диагональную композицию, полупрозрачность и палитру home-wave: шалфейный #98A472, оливковый #7D8F59, серо-зелёный #B0B690, золотистый #E5D29B/#F2E2B5 на #FAF0E5. Без резких пульсаций, вспышек, прямоугольных границ и заметного шва цикла.
- [ ] Начать с небольшого прототипа Canvas 2D или WebGL/Three.js и зафиксировать выбор по качеству формы, профилю кадров и размеру загрузки. Three.js допустим для сложных лент и shader-деформации; его подключение само по себе не считается оптимизацией.
- [ ] Для варианта Three.js использовать небольшое число лент/мешей либо плоскость с текстурой и shader-переливом, если она сохраняет форму концепта. Геометрия, материалы и текстуры создаются при инициализации; на кадре обновляются время/uniforms. Не вводить тяжёлый postprocessing без измеренной необходимости.
- [ ] Сделать модуль `src/modules/home-wave.js` с идемпотентной инициализацией по data-атрибуту и методом destroy. Отсутствие root должно безопасно завершать инициализацию.
- [ ] Подключить из src/entries/index.js; тяжёлый renderer загружать отдельным динамическим import. Текст, CTA и статический фон доступны до загрузки модуля; ошибка загрузки оставляет фон.
- [ ] Добавить canvas в home.hbs и стили в index.scss. Ограничить его областью декора, поставить aria-hidden="true", pointer-events:none, исключить из tab order. Не менять порядок семи секций и якорную навигацию.
- [ ] Сохранить текущий фон до первого успешного кадра. После него исключить двойное наложение статической и живой волны; при ошибке вернуть фон без скачка layout.
- [ ] Оставить Why Luni, Support и card-wave статическими в этой поставке. Массовое создание canvas для всех декоративных элементов не входит в задачу.

## Рабочие допущения и референсы движения

ISPmanager — дополнительный ориентир по пожеланию пользователя: [официальный сайт](https://www.ispmanager.com/). Конкретный экран/ролик и технология его эффекта не установлены. Исполнитель фиксирует использованный URL и короткую запись выбранного эффекта в отчёте, если использует этот ориентир. Не считать доказанным, что ISPmanager использует Three.js; отсутствие точного примера не блокирует работу по home-wave.

Для первого прототипа принять спокойное движение с характерным периодом 12–20 секунд и небольшой амплитудой, не мешающее чтению. Это стартовые параметры для визуальной проверки, не свойства внешнего референса. Анимация не зависит от мыши и не нужна для доступа к содержимому.

## Рендер и бюджет кадра

Ниже — целевые критерии задачи, а не обещание отсутствия пропусков на любом устройстве.

- [ ] Один планировщик requestAnimationFrame; не сочетать его с параллельным setAnimationLoop или таймером рендера. Время движения вычислять по timestamp, не по числу кадров; после паузы сбрасывать базовое время/ограничивать delta, чтобы не было скачка.
- [ ] При видимом Home целиться в 60 fps на экране 60 Hz: общий интервал кадра около 16,7 мс. Начальный бюджет CPU wave-callback — p95 ≤ 4 мс; длительность вызова renderer.render не выдавать за GPU-время.
- [ ] Не читать геометрию DOM, не создавать массивы/материалы/текстуры и не компилировать shaders в цикле. Размеры получать через ResizeObserver и обновлять drawing buffer только при изменении размера/DPR.
- [ ] Ограничить effective DPR максимумом 1,5 и drawing buffer максимумом 2 млн пикселей как стартовые настройки. На слабом устройстве снижать resolution scale и сложность эффекта с гистерезисом, без переключения качества каждый кадр.
- [ ] Если минимальное качество не держит бюджет, переходить к статическому fallback; фиксировать это в отчёте. Намеренный режим 30 fps не представлять как выполнение критерия 60 fps.
- [ ] При уходе #home за пределы viewport (IntersectionObserver) и document.hidden отменять цикл, не просто пропускать draw внутри бесконечного rAF. Возврат запускает только один цикл.
- [ ] При prefers-reduced-motion: reduce показывать статическую волну без постоянного рендера; учитывать изменение настройки во время работы. При нулевом размере контейнера рендер не выполнять.
- [ ] Обработать недоступность WebGL, ошибки shader/текстуры и webglcontextlost: остановить рендер и показать fallback. Восстановление контекста допускается только без дублирования ресурсов/циклов.
- [ ] destroy отменяет rAF, отключает observers/listeners, освобождает GPU-ресурсы и renderer. Повторная инициализация и возврат из bfcache не создают второй canvas/цикл.
- [ ] Не увеличивать разрешение до полного экрана ради небольшой зоны декора. Зафиксировать размеры чанка raw/gzip и загружаемых текстур; сравнить LCP до/после.

## Проверка результата

1. На 375/768/1440 px, DPR 1 и 2 волна сохраняет композицию, не закрывает текст/CTA и не создаёт горизонтальный скролл. Приложить скриншоты и видео 15–20 секунд.
2. Проверить production-сборку в Chrome, Firefox, Safari/WebKit и минимум на одном реальном телефоне. Записать модели CPU/GPU/телефона, ОС, версии браузеров, viewport, DPR и частоту дисплея. Недоступные проверки отметить not-run.
3. На desktop со встроенной графикой и реальном телефоне с экраном 60 Hz выполнить по три записи по 30 секунд после 5 секунд прогрева. Отдельно проверить Home в покое, прокрутку, resize и открытие wishlist.
4. В стационарном тесте целевые пороги: p95 интервала кадров ≤ 18 мс, доля интервалов > 25 мс ≤ 1%, CPU wave-callback p95 ≤ 4 мс, без long tasks > 50 мс, вызванных волной. Интервалы rAF — индикатор планирования; приложить browser Performance trace для проверки пропущенных кадров и GPU-нагрузки, а не только средний FPS.
5. После ухода Home за экран/скрытия вкладки draw-вызовы прекращаются. После десяти циклов pause/resume и init/destroy нет дублирования canvas/listeners и нарастающего числа GPU-ресурсов.
6. Без JS, при reduced motion, ошибке импорта и недоступном/потерянном WebGL остаётся статическая home-wave; ссылки и wishlist сохраняют работоспособность в доступном им режиме.
7. Сравнить LCP со статическим вариантом в одинаковых условиях по медиане трёх холодных запусков: целевой рост не более 100 мс; CLS от canvas равен 0. Если бюджет не выполнен, оптимизировать или оставить fallback до приёмки.
8. Выполнить npm run lint и npm run build:prod; приложить результаты, размеры ассетов и ограничения. Проверки не считать пройденными без фактического запуска.
