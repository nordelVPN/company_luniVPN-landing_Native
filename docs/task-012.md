# task-012 · Реализовать UI/UX и Telegram-вишлист LuniVPN

## Актуальный объём: единый лендинг

Wishlist располагается в общей шапке единого лендинга; на телефоне — в меню. Get Luni → #plans, выбор тарифа → #checkout. UI/UX, тексты диалога, WL-01–14 и backend-требования ниже сохраняются; отдельная страница wishlist не нужна.

Основа: [requirements](requirements.md) и [task-001](task-001.md). Порядок: Home → The app → Why Luni → Support → Plans → Checkout → Account. Эта запись заменяет прежние требования об отдельных страницах и ожидании согласования количества экранов. Выполнение миграции и QA пока не подтверждены.

## Ранее зафиксированные детали и отчёты

Ниже сохранены детали прежней реализации. Упоминания MPA, отдельных HTML и старых зависимостей являются историческими; применять актуальный объём выше.


**Исполнитель:** Frontend — интерфейс и пользовательский сценарий; Backend — бот и запись; DevOps — окружение; QA — приёмка.  
**Статус:** частично реализовано; см. [фактический отчёт](backend/status.md).  
**Первый показ:** посетитель открывает wishlist на сайте, переходит в собственного бота LuniVPN, нажимает Start и получает подтверждение после записи.

## Интерфейс и пользовательский сценарий

- В общей навигации рядом с Get Luni разместить отдельное действие **Join the wishlist**. На узком экране оно доступно в меню. Get Luni по-прежнему ведёт к тарифам.
- По нажатию открыть диалог с заголовком **Join the LuniVPN wishlist**, пояснением **Open our Telegram bot and press Start to join the list for launch updates.** и основной кнопкой **Open Telegram**. Использовать кремовую поверхность, хвойную кнопку и типографику сайта. Добавить видимое действие закрытия.
- Брать ссылку из единой публичной настройки. Пока адрес собственного бота не задан, показать **The wishlist will open soon.** и оставить доступным закрытие. При заданном адресе кнопка открывает бота. После возврата на сайт посетитель может продолжить просмотр.
- Подтверждение регистрации приходит в личном чате после успешной записи. Повторный Start обновляет существующую запись.
- При приёмке проверить оба состояния ссылки на широком и узком экранах, доступное имя диалога, открытие с клавиатуры, фокус внутри окна, закрытие по Escape и возврат фокуса к действию открытия. После перехода из мобильного меню вернуть фокус к доступному элементу навигации.

## Зависимости

Перенос и локальные тесты независимы от Account/Billing и согласования demo B. Сборка site зависит от task-005, UI — от общей оболочки task-006; рабочая точка входа описана выше. Для сквозного прогона нужны собственные токены и URL бота. Для production — постоянный HTTPS origin и выбранный runtime; существующий frontend deploy бота не развёртывает.

## Рабочие допущения

Основа Nordel разрешена к использованию пользователем. Копировать только код и шаблоны конфигурации, не .env и данные. PHP webhook и JSON — MVP для одного узла. Массовые рассылки, платежи, аккаунт, VPN и масштабирование не включены. Повторный ответ при повторной доставке допустим; дубликат пользователя — нет.

## Проверка результата

Критерии — WL-01–14 и [матрица приёмки](backend/wishlist-validation.md). Закрытие задачи требует рабочего перехода сайт → Telegram → /start, сохранности после пересоздания, отрицательных HTTP-проверок и отчёта. Отсутствующие внешние проверки не отмечать выполненными.
