# Проверка описаний коммитов

## Правила для новых коммитов

Каждый новый коммит связывать с задачей из [реестра](tasks.md). В сообщении указывать содержательный заголовок с ID задачи, затем описание: что и зачем изменено, какие проверки выполнены и какие ограничения остались. Для нескольких задач перечислить все затронутые ID. Для документации допустима проверка ссылок и согласованности; непроведённые проверки указывать прямо.

Пример формата (не результат выполненной работы):

```text
docs(LUNI-DOC-001): согласовать документацию публичного сайта

Изменения: <фактические изменения и причина>.
Проверки: <выполненные проверки и результат>.
Ограничения: <что осталось или не проверялось>.
Задача: docs/tasks.md — LUNI-DOC-001.
```

Менеджер читает сообщение и diff, сверяет их с задачей и отчётом. Наличие текста без соответствия изменениям не закрывает проверку. Для каждого проверенного коммита записываются SHA, задача, фактические изменения, полнота описания и замечания. SHA записывать после появления коммита в следующем обновлении журнала: собственный SHA внутри коммита заранее неизвестен.

Исторические сообщения не переписывать ради нового правила. Недостающий контекст фиксировать здесь; историю менять только по отдельному запросу.
